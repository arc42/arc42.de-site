Usage: {% include resource-item.html resource=item %} Fields (from _resources/*.md front matter): type book | article | talk | video (required) title string (required) language en | de (required) year integer (optional; undated items sort last) summary one-line description (required) search extra keywords for the filter (optional; title + summary are searched anyway) cover thumbnail path (optional; falls back to a letter marker) link URL (optional; omit for "no link" items) link_label CTA text (optional; arrow is derived from the link) id anchor id (SEE BELOW — inert) ANCHORS. Every card gets `id=""`, derived from `r.path`, so /publikationen/#arc42-by-example-vol2 works for every entry without anyone having to declare anything. It deliberately does NOT read the front-matter `id:` field. Jekyll's DocumentDrop defines `id` as a method returning the document's internal id (`/publikationen/arc42-by-example-vol2`), and a drop method WINS over a front-matter key of the same name — so `{{ r.id }}` rendered `id="/publikationen/arc42-by-example-vol2"`, an anchor no link could ever reach. The `id:` keys still present in two _resources files are kept only so those files stay byte-identical with their arc42.org twins; their values happen to equal the filename slug, which is what this now emits anyway. {%- endcomment -%} {%- assign r = include.resource -%} {%- assign r_anchor = r.path | split: '/' | last | split: '.' | first -%} {%- assign lang = 'Englisch' -%}{%- if r.language == 'de' -%}{%- assign lang = 'Deutsch' -%}{%- endif -%} {%- case r.type -%} {%- when 'book' -%}{%- assign type_label = 'Buch' -%} {%- when 'article' -%}{%- assign type_label = 'Artikel' -%} {%- when 'talk' -%}{%- assign type_label = 'Vortrag' -%} {%- else -%}{%- assign type_label = 'Video' -%} {%- endcase -%}

The href is DERIVED as /info-/ and is deliberately NOT taken from course.url — that field is an absolute https://www.arc42.de/... link, and `make test-theme` fails the build if that host appears anywhere in _site. An unknown id resolves to nil and renders nothing, so a typo degrades to "no second line" rather than a broken link.

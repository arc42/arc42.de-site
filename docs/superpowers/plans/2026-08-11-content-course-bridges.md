# Content → Course Bridges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every relevant publication on arc42.de a route to a bookable course, and close four content pages with one conversion band each.

**Architecture:** Two independent additions to a Jekyll 4.3 site. (A) An optional `course:` key in `_resources/*.md` front matter; `_includes/resource-item.html` resolves it against `site.data.trainings.courses` and renders a second link line to `/info-<id>/`. (B) A new `_includes/course-bridge.html` that finds the next bookable date with the same key-sort `_includes/timeline_auto.html` already uses, and renders it in one of two variants. No existing behaviour changes; both parts are additive.

**Tech Stack:** Jekyll 4.3 + Liquid, plain CSS (no Sass for these files), Docker-based build via `make`. There is no unit-test framework for Liquid — the test harness is `make site` followed by structural assertions (grep) against the generated `_site`, which is exactly what `make test-theme` already does.

**Spec:** `docs/superpowers/specs/2026-08-11-content-course-bridges-design.md`

## Global Constraints

Every task's requirements implicitly include this section.

- **Never emit `https://www.arc42.de`.** `make test-theme` greps all of `_site` for that host and fails the build. `_data/trainings.json` stores exactly that in `course.url` (`https://www.arc42.de/info-msa/`) and `date.url` (`https://www.arc42.de/termine#msa-dez-2026`). **Never output those two fields.** Build course links as `/info-<id>/` instead.
- **Every internal link ends with `/` before any `#`.** `make test-theme` fails on `href="/termine"` and on `href="/termine#anchor"`. Correct: `/termine/`, `/termine/#anchor`, `/info-msa/`, `/schulungen/`.
- **No absolute same-site anchors.** `<a href="https://arc42.de/…">` also fails `make test-theme`.
- **Never hand-edit `_data/trainings.json`.** It is generated by `.github/workflows/refresh-trainings.yml`; every manual change is overwritten at the next sync.
- **No new stylesheet and no new `@import` in `assets/css/main.scss`.** Dart Sass emits `@import 'x.css'` as a plain `@import url(x.css)`, which places the imported sheet *before* the theme, so it loses every specificity tie. All new CSS goes at the end of `assets/css/arc42-resources.css`, which already holds `:root`, `.btn--arc42` and `.resource-*`.
- **No twelfth button colour.** `assets/css/button.css` already ships eleven against a four-colour `DESIGN.md`. The band uses the existing `.btn--arc42` and `.btn--arc42-outline` only.
- **Buttons are anchors, never `<a><button>`.** That nested pair is the 44-instance defect item 6 of `IMPROVEMENT_PLAN.md` has to unpick; do not create more. `.btn` already carries `display:inline-block` and `text-decoration:none`.
- **The `:visited` trap.** Minimal Mistakes sets `a:visited { color:#4e91a5 }` at specificity (0,1,1), which beats `.btn--arc42` at (0,1,0), and the custom sheets load *before* the theme so ties are lost too. Every colour-setting rule on an anchor in this work must be written to survive `:visited`. Verify in both states.
- **Copy is frozen** per spec §5.3 and is reproduced verbatim in the tasks below. Do not paraphrase. One deviation is called out and flagged in Task 3, Step 1.
- **Branch:** `improve-the-flow`. The working tree carries unrelated uncommitted work (item 1, plus untracked company-logo files). **Stage only the files each task names** — never `git add -A`, never `git add .`.

```liquid
{%- comment -%}
  Conversion band that closes a content page with the next bookable course date.

    {% include course-bridge.html %}                      -> card (default)
    {% include course-bridge.html variant="card" %}
    {% include course-bridge.html variant="hairline" %}

  Exactly ONE band per page, always last. That is the ceiling, not the starting
  point — this is a library, not a funnel.

  Next-date lookup is the same key-sort timeline_auto.html uses: build
  "start|courseIndex|dateIndex" strings (ISO dates sort lexicographically),
  sort, take the first. ONE deliberate difference: this include also skips
  waitlist/full, because a sold-out date is a bad call to action, whereas the
  timeline shows those on purpose.

  No price is shown anywhere. `pricing` is German prose rather than a number
  ("Frühbucherpreis ... € 2690, Normalpreis: € 2890") and only MSA dates carry
  it — the next open date usually has none. See spec section 3.

  Links are written out as /termine/ and /schulungen/. Never emit date.url or
  course.url: both are absolute https://www.arc42.de/... addresses, and
  `make test-theme` fails the build if that host appears anywhere in _site.
{%- endcomment -%}
{%- assign variant = include.variant | default: 'card' -%}
{%- assign crs = site.data.trainings.courses -%}
{%- assign today = 'now' | date: '%Y-%m-%d' -%}
{%- assign keys = "" | split: "" -%}
{%- for c in crs -%}
  {%- for d in c.dates -%}
    {%- if d.status == "cancelled" or d.status == "waitlist" or d.status == "full" -%}{%- continue -%}{%- endif -%}
    {%- if d.end < today -%}{%- continue -%}{%- endif -%}
    {%- capture k -%}{{ d.start }}|{{ forloop.parentloop.index0 }}|{{ forloop.index0 }}{%- endcapture -%}
    {%- assign karr = k | split: "~~" -%}
    {%- assign keys = keys | concat: karr -%}
  {%- endfor -%}
{%- endfor -%}
{%- assign sorted_keys = keys | sort -%}
{%- assign nc = nil -%}
{%- assign nd = nil -%}
{%- assign datelabel = nil -%}
{%- if sorted_keys.size > 0 -%}
  {%- assign parts = sorted_keys[0] | split: "|" -%}
  {%- assign ci = parts[1] | plus: 0 -%}
  {%- assign di = parts[2] | plus: 0 -%}
  {%- assign nc = crs[ci] -%}
  {%- assign nd = nc.dates[di] -%}
  {%- capture datelabel -%}{%- include training-date-label.html date=nd lang="de" style="long" -%}{%- endcapture -%}
{%- endif -%}
{%- if variant == 'hairline' -%}
<aside class="course-bridge course-bridge--hairline" aria-label="Schulungen">
  <p class="course-bridge__kicker">Nächster Termin</p>
  <p class="course-bridge__text">Wir unterrichten, worüber wir schreiben:{% if nd %} <b>{{ nc.short_title | default: nc.title }} &mdash; {{ datelabel }}{% if nd.city %} in {{ nd.city }}{% endif %}</b>{% if nc.certification %}, mit Zertifizierung nach {{ nc.certification }}{% endif %}.{% else %} in offenen Schulungen mit iSAQB-Zertifizierung.{% endif %}</p>
  <a class="course-bridge__link" href="/termine/">Alle Termine ansehen <span aria-hidden="true">&#8594;</span></a>
</aside>
{%- else -%}
<aside class="course-bridge course-bridge--card" aria-label="Schulungen">
  <p class="course-bridge__kicker">Schulungen</p>
  <h2 class="course-bridge__title">Diese Themen gibt es auch als Training</h2>
```
